## 🔴 CRITICAL — Live system risk or broken mechanism

### 1. Backups stale — 23 days [ROOT CAUSE FOUND]
**Source:** Live audit. Latest `D:\AI\Backups\smisel_live\` is `2026-07-07T11-05-31`.
**Investigation result:** `smisel_nightly_loop.py` (464 lines) does NOT include any backup step. Its pipeline is: kanon → graph extract → curator → reference index → reflection → apply context. The backup mechanism (`Ops\space-control\scripts\backup_smisel_live_hot.ps1`) is a **manual, standalone PowerShell script** with no scheduled trigger whatsoever. The nightly loop re-enablement on 2026-07-29 did not restore backups because backups were never automated.
- **What's at risk:** The only recovery path for WorkShade data. C-drive rollback folders were retired; no C-based recovery exists. A disk failure or accidental rm would lose 23 days of data.
- **Fix required:** Either (a) add `Invoke-SmiselHotBackup` call to the nightly loop's post-chain in `smisel_nightly_loop.py`, or (b) create a separate Windows scheduled task that runs `backup_smisel_live_hot.ps1` on its own schedule. Option (a) couples backup to loop success; option (b) is more robust but adds a third trigger to manage. The nightly loop trigger (`trigger_nightly_loop.py`) already has a fail-closed preflight and runs headless via `pythonw.exe` — the same pattern would work for a dedicated backup task.
